# 약물운전 확인 서비스 — 프로젝트 현황 요약
(2026.8.10 기준)

## 1. 프로젝트 목표

사용자가 약 이름을 검색하면, "이 약을 먹고 운전해도 되는지"를 참고할 수 있도록
- 운전에 영향을 줄 수 있는 성분 여부와 등급(Level)
- 실제 공식 문서(e약은요·약학정보원)의 경고문구
를 함께 보여주는 서비스.

---

## 2. 데이터 구조 (3개 축)

| 축 | 내용 | 출처 |
|---|---|---|
| ① 위험도 분류 | 386개 성분, Level 0~3 등급 + 증상(졸음/어지러움/시야흐림/충동성·공격성/저혈당) | 대한약사회 참고자료 (공식 가이드라인 아님) |
| ② 성분↔제품 매칭 | 성분명으로 실제 시판 제품을 찾아 연결 | 식약처 공공데이터 API |
| ③ 실제 경고문구 | 개별 제품의 공식 첨부문서 경고 문장 | e약은요 API / 약학정보원(수동 보완) |

## 6. 핵심 기술적 발견 / 수정 이력

1. **매칭 순서 의존 버그**: 성분명이 다른 성분명에 부분 포함될 때(예: 코데인⊂디히드로코데인) 잘못된 성분으로 매칭될 위험 → "가장 긴 이름 우선" 방식으로 근본 수정
2. **API 페이지네이션**: 한 번에 최대 300건만 반환 → `page_no` 파라미터로 여러 페이지 이어받기 구현
3. **API 서버 불안정**: 타임아웃/504 에러 간헐 발생 → 재시도 로직(3회) + 성분/페이지 단위 수동 분할 실행으로 대응
4. **표기 공백 문제**: 386리스트 원본에 공백·슬래시 포함된 성분명(예: "슈도에페드린 염산염/황산염")을 그대로 검색어로 쓰면 0건 → 공백 제거 후 재검색으로 881건 추가 확보
5. **마약류는 이 API로 처리 불가**: `getDrugPrdtMcpnDtlInq07` API는 마약류·향정신성의약품을 아예 다루지 않음 (별도 관리 시스템) → 마약류(542개)는 데이터 적용 대상에서 제외하기로 결정, 별도 공시 예정

## 7. 법률 검토 결과 (중요, 정정된 내용)

- **틀렸던 초기 이해**: "도로교통법상 처벌 대상은 마약류에 한정된다" → 이는 부정확함
- **정정된 사실**: 도로교통법 제45조는 약물의 종류와 무관하게, **복용 후 정상적인 운전이 가능했는지(운전자의 상태)**를 기준으로 처벌 여부를 판단함. 감기약 등 일반의약품도 처벌 대상이 될 수 있음.
- 2026년 개정으로 처벌 강화(5년 이하 징역 또는 2천만원 이하 벌금), 타액 간이시약 검사 등 단속 방식 구체화.

## 8. 화면(UI) 설계 원칙 (프로토타입 반영 완료)

1. 운전등급(Level)이 주인공, 경고문구는 보조 정보
2. 복합제는 매칭된 성분 전부 표시 (대표 등급 하나로 뭉치지 않음)
3. 단정형 표현 금지 ("위험합니다" ×, "주의가 필요한 것으로 확인됨" ○)
4. 등급 출처와 경고문구 출처를 각각 별도로 명시
5. "등급은 있으나 경고문구 없음" 상태에 대한 안내 문구 별도 마련
6. 동일 제품명, 여러 용량/제형 존재 시 목록에서 구분 표시
7. 화면 하단 고정 면책 문구 + "법적 근거 자세히 보기" 접이식 패널
8. 마약류 미포함 안내 문구 검색창 하단 상시 노출

## 9. 아직 남은 것 (우선순위 낮음, 필요시 진행)

- 우황청심원류(59건)에 대한 UI 안내 문구 별도 설계 ("한약재 성분으로 평가 대상 아님" 등)
- 플루비프로펜/플루르비프로펜 점안액 케이스처럼, 앞으로도 나올 수 있는 표기 차이 지속 모니터링
- 386리스트의 "생지황, 현삼, 당귀..." 식 한약재 나열형 표기 자체는 원본 자료의 한계로, 별도 대응 불필요(구조적으로 정상적인 매칭 불가 케이스)
- 프로토타입 데이터셋을 9,114개 최종본 기준으로 추가 보강 가능 (현재는 대표 샘플 몇 건만 반영)
